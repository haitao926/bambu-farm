# 校园拓竹打印机集群管理系统 - 开发计划 (Development Roadmap)

## 阶段一：基础设施与原型验证 (Week 1-2)
**目标**：跑通“上传 -> 打印”的核心链路，验证技术可行性。

1.  **环境搭建**：
    *   配置 Docker Compose (PostgreSQL, Redis, Go2RTC)。
    *   初始化 Monorepo (Next.js + NestJS)。
2.  **核心库测试**：
    *   编写测试脚本，使用 `bambu-node` 连接 1 台局域网内的拓竹打印机。
    *   验证 MQTT 状态订阅（获取温度、状态）。
    *   验证 FTPS 文件上传功能。
3.  **基础功能开发**：
    *   数据库设计（Printer, Job, User 表）。
    *   后端：实现简易的“上传文件 -> 触发打印”接口（无审核逻辑）。
    *   前端：简易控制台，显示打印机连接状态。

## 阶段二：业务逻辑与审核流 (Week 3-4)
**目标**：实现完整的“学生-老师”闭环流程。

1.  **调度系统 (Scheduler)**：
    *   实现 20 台机器的连接池管理。
    *   开发自动轮询与空闲检测逻辑。
    *   实现任务队列 (BullMQ)，处理并发任务与重试机制。
2.  **业务界面开发**：
    *   **学生端**：模型上传组件（集成 .3mf 解析预览）、状态进度条。
    *   **教师端**：待办事项列表、审核模态框（集成 3D 预览）、一键批准。
3.  **用户系统**：
    *   简单的 JWT 登录鉴权。
    *   区分学生与教师权限。

## 阶段三：监控与通知 (Week 5)
**目标**：提升可用性，实现远程“看一眼”。

1.  **视频流集成**：
    *   配置 Go2RTC 自动发现或静态配置 20 路 RTSP 地址。
    *   前端集成 WebRTC 播放器，实现低延迟观看。
2.  **通知系统**：
    *   集成 Apprise 或直接调用 Webhook（企业微信/钉钉）。
    *   配置关键节点通知：审核通过、开始打印、打印完成、故障报警。

## 阶段四：部署、测试与优化 (Week 6)
**目标**：在真实网络环境下稳定运行。

1.  **网络部署**：
    *   配合网管配置 VLAN。
    *   服务器部署与防火墙设置。
2.  **压力测试**：
    *   模拟 20 台设备同时在线的心跳包压力。
    *   测试大文件 (100MB+) FTP 并发上传稳定性。
3.  **UI/UX 优化**：
    *   添加错误处理与引导提示。
    *   优化移动端适配（方便学生手机查看）。

## 备忘录：所需硬件准备
*   **服务器**：x86 主机 (i5/i7, 16G RAM, 512G SSD) 或高性能工控机。
*   **网络**：千兆交换机，确保服务器与打印机之间带宽充足。
